# 价格曲线纵轴文字不缩放设计

## 问题

价格曲线和纵轴使用两个独立 SVG。曲线 SVG 的宽高会近似等比放大，但纵轴 SVG 的宽度保持为刻度文字所需的窄列，高度却随弹窗拉伸。纵轴设置了 `preserveAspectRatio="none"`，因此浏览器分别缩放横向和纵向坐标，SVG 文字随纵向比例变形，视觉上表现为文字被压窄、拉高。

## 方案比较

1. **用 HTML 刻度文字替代纵轴 SVG 文字（采用）**：刻度位置按绘图区高度换算为百分比，字体使用普通 CSS 像素渲染。纵轴仍随弹窗伸展，文字位置与网格线同步，但字形不参与 SVG 变换。
2. **把整个图表固定为 250px 高**：改动最小，但会浪费弹窗的可用高度，也改变当前大图显示效果。
3. **对每个 SVG 文字应用反向缩放**：能够抵消当前比例，却必须持续读取实际高度并维护反向变换，复杂且容易在响应式尺寸下产生偏移。

## 最终设计

- 保留曲线 SVG、网格线、折线、数据点和拖拽逻辑不变。
- 将纵轴容器从 `<svg>` 改为普通 `<div>`。
- `renderHistoryLineChartFrame()` 根据每个纵轴刻度原有的 Y 坐标，计算相对于 250 高度的百分比位置。
- 每个刻度使用绝对定位的 `<span class="history-line-y-label">`，通过 `translateY(-50%)` 让文字中心对齐对应网格线。
- 纵轴容器使用当前面板背景色，宽度仍由刻度文字长度动态计算。
- 拖动或切换时间范围时继续只替换纵轴容器内容，无需读取或修改 SVG `viewBox`。

## 保持不变的行为

- 纵轴仍为五级等差刻度，并随当前可见区间重新计算。
- 两位小数及必要时提高精度的逻辑不变。
- `7d`、`30d`、全部历史、异常值和数据点开关、红涨绿跌以及拖拽手势不变。
- 桌面端和移动端使用同一套百分比定位。

## 验证

- 回归测试确认纵轴不再使用 SVG 或 `preserveAspectRatio="none"`，并存在绝对定位的 HTML 刻度样式。
- 运行完整单元测试、JavaScript 语法检查、差异检查和 Worker dry-run。
- 使用本地合成历史在实际弹窗高度下验证：纵轴文字字形正常，刻度中心与横向网格线对齐；切换范围和拖动后仍保持对齐；浏览器控制台无错误。
